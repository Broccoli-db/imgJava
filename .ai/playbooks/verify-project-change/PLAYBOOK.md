# Playbook：验证 Java 改动

1. 读取 `AGENTS.md`、`.ai/CHECKLIST.md`、`.ai/rules/testing.md` 和本目录 `checklist.md`。
2. 检查工作区和目标 diff，按风险选择验证，不默认运行全部命令。
3. 从 `pom.xml` 或 `build.gradle` 获取真实任务，使用项目构建包装器。
4. 先运行便宜的编译、静态检查和目标测试，再决定是否扩大到完整构建、集成测试或容器化测试。
5. API、数据库、认证、消息和生命周期改动必须覆盖对应失败路径。
6. 不安装新依赖，不访问生产数据，不修改外部只读目录。
7. 区分通过、失败、阻塞和未验证，禁止用静态检查替代行为验证。

输出简洁验证报告，包括命令、结果、失败原因和残余风险。
