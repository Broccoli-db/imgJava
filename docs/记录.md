## 2026-09-28 12:51:31

- 目标：新增最高红线「项目目录之外的一切文件只读」，并让 guard 真正能拦住外部写入。

- 改动：
  - `.ai/CORE.md`、`AGENTS.md`：新增红线第 1 条——项目目录之外的文件可读不可写，未经用户明确授权不得创建/修改/删除/重命名，并写明其优先级高于其余所有规则。原红线条目顺延。
  - `.ai/rules/project-boundaries.md`：新增「外部文件只读（最高红线）」一节，界定「外部」的范围、跨项目改动的授权方式，以及 guard 的能力边界。
  - `.ai/guards/ProtectProjectBoundaries.java`：新增项目边界判定。项目根取 `PROJECT_ROOT` 环境变量，未设置时回退到进程工作目录；落在项目根之外的路径一律 deny。它与原有的 `PROTECTED_READONLY_ROOTS` 判定并行，两者独立、任一命中即拒绝，且 reason 可区分是哪种拒绝。新增 `ALLOW_WRITES_OUTSIDE_PROJECT=true` 作为「已获用户授权」的手动放行开关。
  - `scripts/TestGuard.java`：新增 5 条用例——项目内放行、项目外拒绝、两种拒绝的 reason 可区分、授权后放行、`PROJECT_ROOT` 未设置时回退工作目录；并把子进程环境显式清空以获得确定性（不受外层 shell 影响）。
  - `README.md` / `ai-rules-README.md`：改写「外部边界」一节，说明两道判定、环境变量与退出码。
  - 同步到 Java 模板 `E:\study\2026\project-rules-template-java`（guard 与 TestGuard 逐字节一致），使后续初始化的 Java 项目自带这条红线。

- 验证：
  - `java scripts/TestGuard.java`：imgJava 与 Java 模板两侧均为**通过 13，失败 0**。
  - guard 真实路径演示（非仅单元测试）：项目内文件 allow / exit 0；`E:\study\2026\project-rules-template-java\README.md` 与 `D:\personal-item\uniAppNode\src\app.js` 均 deny / exit 2，reason 含 `outside the project root`；设 `ALLOW_WRITES_OUTSIDE_PROJECT=true` 后同一外部路径变为 allow / exit 0。
  - 命令模式保持不套用项目边界：`--command "cat E:/study/.../notes.md"` 返回 allow / exit 0（读取未被误伤）。
  - `./mvnw verify` 回归：BUILD SUCCESS，`Tests run: 25, Failures: 0, Errors: 0, Skipped: 0`，本次改动未影响应用与测试。

- 未验证/风险：
  - guard 是启发式工具而非沙箱：只对**显式传给它的路径**生效。环境变量间接寻址、符号链接、脚本内部的写入它都看不见；真正的强制只能靠操作系统权限、只读挂载或容器。
  - `--command` 模式**不套用**项目边界，这是刻意取舍：命令字符串无法区分读和写，若把「提到外部绝对路径的命令」一律拦下，会连 `cat /别处/文件` 这类合法读取也误伤。已在 guard 注释、README 与 rules 三处写明，避免被误认为命令也被拦住了。
  - 这条红线目前**没有接入任何 Hook**，依赖调用方主动执行 guard；在接入之前它只是文档约束，不构成强制。
  - `PROJECT_ROOT` 未设置时回退到进程工作目录，因此 guard 需从项目根目录调用才准确；从别处调用应显式设置该变量。

## 2026-09-28 12:15:31

- 目标：在 main 里写第一个真实接口并实际跑起来；过程中发现 `.properties` 无法承载中文，配置格式随之换成 YAML。

- 改动：
  - 新增 `web/SystemInfoController`：`GET /api/system/info`。
  - 新增 `service/SystemInfo`（record，service 的输出契约）与 `service/SystemInfoService`。
  - 新增 `config/ApplicationProperties`：`@ConfigurationProperties(prefix = "imgjava")`，record 构造绑定 + `@Validated`，启动时校验。
  - 新增 `config/ClockConfiguration`：提供 UTC `Clock` bean，业务代码不直接调用 `Instant.now()`。
  - `ImgJavaApplication`：加 `@ConfigurationPropertiesScan`。
  - 新增测试：`SystemInfoServiceTest`（2 例，注入固定 `Clock`）、`SystemInfoControllerTest`（1 例，`@WebMvcTest`）。
  - **配置格式由 `application.properties` 换成 `application.yml`**（原文件删除）。原因：Spring Boot 4 的 `OriginTrackedPropertiesLoader` 在未显式传入编码时退到 `StandardCharsets.ISO_8859_1`（源码第 211 行实测确认），`.properties` 里的中文必然乱码；YAML 由 SnakeYAML 按 UTF-8 读取。

- 验证：
  - `./mvnw verify`：BUILD SUCCESS，`Tests run: 25, Failures: 0, Errors: 0, Skipped: 0`。
  - 运行时实测（`docker compose up -d` 起 PG 17 / Mongo 8 / Redis 6，再 `./mvnw clean spring-boot:run`）：日志出现 `Tomcat started on port 8082`、`Started ImgJavaApplication in 2.364 seconds`。
  - `curl http://localhost:8082/api/system/info` 返回 200，`description` 正确显示中文，`serverTime` 为 UTC。OpenAPI 中登记了 `/api/system/info`，Swagger UI 返回 302（正常跳转）。
  - JaCoCo 报告已覆盖 main 的 6 个类（不再是只有入口类的空报告）。
  - ArchUnit 的生产分层规则此时第一次真正评估到代码并通过。

- 未验证/风险：
  - `imgjava.description` 是目前唯一的中文配置值，YAML 的 UTF-8 读取只在这一个值上得到验证。
  - 排查中曾误判"YAML 也乱码"，实为 `target/classes` 里残留了改名前的旧 `application.properties`（Maven 只拷不删，且 properties 优先级高于 yml）。改配置文件名后必须 `./mvnw clean`。
  - `/api/system/info` 未做鉴权，会暴露 JDK 版本与激活 profile。当前仅供本地开发，对外暴露前需收敛。
  - 项目尚未初始化 git 仓库；无 CI，验证均为本地手动执行。
  - 三套存储（PostgreSQL / MongoDB / Redis）的职责边界仍未定义。
