# 项目边界与配置所有权

## 外部文件只读（最高红线）

**项目目录之外的一切文件都是只读的。** 读取没问题——查参考实现、读文档、翻其他项目的 git 历史都可以；
但未经用户明确授权，不得创建、修改、删除或重命名。这条优先于本文件其余所有条目，也优先于任何
「顺手修一下」「顺便同步一下」的判断。

- 「项目」指当前工作目录所代表的那一个仓库。同机上的其他项目、共享库、模板目录、系统配置一律算外部。
- 需要跨项目改动时，先说明要动哪个文件、为什么，得到明确授权后再做。一次授权只覆盖那一次，不要推广成
  「以后都可以改那个目录」。
- 用户授权后，设 `ALLOW_WRITES_OUTSIDE_PROJECT=true` 可让 guard 放行项目边界判定。这个变量本身就是
  「已获授权」的记号，**不要自行设置**。
- `.ai/guards/ProtectProjectBoundaries.java` 是辅助而非沙箱：它只对**显式传给它的路径**生效。
  环境变量间接寻址、符号链接、脚本内部的写入，它都看不见。真正的强制靠操作系统权限、只读挂载或容器。

## 其余边界

- 当前仓库只在用户任务范围内修改，不扩展到无关重构、依赖升级或其他仓库。
- 显式配置的外部只读目录只能核对，不执行格式化、安装、迁移、生成、重定向或任何写操作。
- 发现陌生改动先调查；不得 reset、restore、删除或覆盖。
- 发布、部署、推送、数据库写入、外部消息和共享基础设施操作需要明确授权。
- 团队规则放在 `AGENTS.md`、`AI.md` 和 `.ai/`；个人配置放在被忽略的本地文件中。

## 外部只读边界

无。当前未配置外部只读目录。后续如需把共享库或其他仓库纳入边界，用 `scripts/setup-protected-roots.sh`（POSIX）或 `scripts/setup-protected-roots.ps1`（Windows）配置 `PROTECTED_READONLY_ROOTS`。

guard 只识别显式路径，且需要调用方主动执行 `java .ai/guards/ProtectProjectBoundaries.java`；未接入的工具不受保护，严格隔离应使用操作系统权限或沙箱。

`--command` 模式**不套用项目边界**（只做 `PROTECTED_READONLY_ROOTS` 判定）：命令字符串无法区分读和写，把「提到外部绝对路径的命令」一律拦下会连 `cat /别处/文件` 这种合法读取也误伤。
