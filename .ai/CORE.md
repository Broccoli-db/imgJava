# CORE - 项目红线

## 红线

1. **项目目录之外的一切文件视为只读**：可以读取，但未经用户明确授权，不得创建、修改、删除或重命名。
   本条优先级高于本文件其余所有规则，也高于任何「顺手修一下」「顺便同步一下」的判断。跨项目改动
   必须先说明要动哪个文件、为什么，得到明确授权后再做；一次授权只覆盖那一次，不要推广成「以后都
   可以改那个目录」。
2. 显式配置的外部只读目录（`PROTECTED_READONLY_ROOTS`）绝不修改；工具级 guard 只是辅助，不是完整沙箱。
3. 未获明确授权，不执行强制推送、硬重置、删分支、发布、部署、生产数据库或共享环境写操作。
4. 不读取、回显、提交或记录 secret；示例配置必须使用明显的无效占位值。
5. 不臆造 HTTP、数据库、消息、缓存或权限契约；不确定时保留 `[待确认]`。
6. 不覆盖、回退或删除来源不明的工作区改动。
7. 不把 mock、静态分析或单元测试结果描述成真实端到端验证。

## Java / Spring 基本约定

1. 启动时校验必需配置，失败时快速退出并给出不泄密的错误信息。
2. 所有请求输入、消息、Webhook 和外部服务响应都在边界验证；内部类型不能代替运行时校验。
3. 认证与授权分别处理；每个资源访问检查调用方是否有权操作该资源。
4. 统一异常处理负责对外响应；内部异常保留 cause/上下文，对外隐藏实现和堆栈。
5. 数据库写入考虑事务、唯一约束、幂等性和并发；迁移不得依赖手工生产操作。
6. 进程处理 `SIGTERM`/`SIGINT`，停止接收新流量并有界等待请求、连接、消费者和日志刷新。
7. 并发任务必须有超时、取消或上限；异步结果必须处理异常分支；重试只用于可重试错误并采用退避。
8. 不吞 `InterruptedException`；中断状态要么继续传播，要么在恢复后重新设置。

## 阻塞行为

- 缺少契约：指出缺失来源并请求确认，不自行发明。
- 缺少环境：说明哪些验证未执行，不用伪造数据冒充通过。
- 发现疑似凭据：停止纳入变更，只报告文件位置和处理建议，不输出内容。
