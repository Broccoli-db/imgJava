# imgJava Java 开发须知

## 开始开发前

1. 使用项目声明的 JDK 版本和构建包装器（`./mvnw` 或 `./gradlew`）。
2. 先读构建文件、应用入口、配置绑定类、统一异常处理和相关测试。
3. 确认项目的包结构、依赖注入方式和持久化选型，不在普通需求中迁移。
4. 查看工作区已有改动，不覆盖、不回退、不清理来源不明文件。

## 必须遵守

- 外部输入在 Controller、消息消费者、Webhook 等边界验证，内部类型不能代替运行时校验。
- Controller 不堆业务逻辑；Service 不直接拼 HTTP 响应；Repository 不承载业务编排。
- 异常交给统一异常处理；catch 只用于恢复、转换、补充上下文或清理。
- 配置集中绑定并在启动时验证，业务代码不散落读取环境变量。
- 数据库使用参数化查询和约束；多步写入根据一致性要求使用事务。
- 认证后仍要校验角色、租户和资源所有权。
- 外部请求有超时；重试有上限；批量处理有并发上限；后台任务处理失败与关闭。
- 日志脱敏，不记录 Authorization、cookie、密码、token、私钥或完整敏感请求体。
- 不提交本地 profile 配置、密钥库、日志、构建产物和个人 AI 状态。

## 常见反例

```java
// 反例：在字段初始化或构造函数中执行 I/O，容器启动与测试都受牵连。
@Service
class ReportService {
    private final Connection connection = openConnection();
}
```

```java
// 反例：吞掉异常并制造“成功但无数据”。
try {
    return repository.findById(id);
} catch (Exception e) {
    return null;
}
```

```java
// 反例：未限制并发，输入规模由调用方和公共线程池决定。
ids.parallelStream().forEach(this::process);
```

```java
// 反例：吞掉中断，破坏取消与优雅关闭语义。
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    // 忽略
}
```

正确实现应遵循项目已有模式：入口显式启动、统一异常处理、有界并发、可测试的依赖边界。
