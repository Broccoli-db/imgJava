# Java 开发规范

## 1. 运行环境

| 维度 | 项目选型 |
|---|---|
| JDK | 25 |
| 构建工具 | Maven（Wrapper 3.3.4 / Maven 3.9.16） |
| 框架 | Spring Boot 4.1.1（`spring-boot-starter-webmvc`） |
| 数据库/持久化 | PostgreSQL 17（JPA/Hibernate）+ MongoDB 8 + Redis 6 |
| 数据库迁移 | Flyway |
| 校验方式 | Jakarta Bean Validation |
| 测试框架 | JUnit 6 + Spring Boot Test + Testcontainers 2 + ArchUnit |
| 覆盖率 | JaCoCo 0.8.15（只出报告，不设门槛） |
| 运行形态 | 可执行 JAR（spring-boot-maven-plugin） |

以仓库实际配置为准。第 2 节的推荐边界是目标分层，项目当前只有入口类，尚未建立分层。

## 2. 推荐边界

```text
src/main/java/<根包>/
  Application.java   # 入口，只负责启动
  config/            # 配置绑定与容器装配
  web/               # Controller、请求/响应 DTO、参数映射
  service/           # 业务用例
  repository/        # 数据访问
  domain/            # 领域模型与实体
  exception/         # 异常类型与统一异常处理
  client/            # 外部服务客户端
  jobs/              # 定时任务与消费者
  shared/            # 日志、通用基础设施
src/main/resources/
  application.yml
  db/migration/      # 迁移脚本
src/test/java/<根包>/
```

不要为了匹配模板强行重排已有项目；优先沿用仓库已经清晰工作的结构。

## 3. 配置

- 在唯一的配置绑定类读取外部配置，用约束注解完成类型转换、范围和必填校验。
- secret 不提供可工作的默认值；错误信息只显示属性名，不显示属性值。
- `application-local.*` 等本地 profile 只放本机覆盖项且不提交；示例文件只放属性名和安全占位值。
- 测试使用独立 profile 或测试属性源，避免与本地开发配置互相污染。
- 生产关键开关（schema 生成策略、调试端点、详细错误信息）必须有安全默认值。

## 4. HTTP API

- 路径、query、body、header、文件和第三方回调都执行运行时校验。
- Controller 只完成协议转换：解析输入、调用用例、映射响应。
- 采用项目统一异常类型和错误响应结构，不把内部异常消息直接返回客户端。
- 正确区分 400、401、403、404、409、422、429 和 5xx；以项目契约为准。
- 列表接口必须有最大分页限制，排序字段使用 allowlist。
- 不把持久化实体直接作为对外 DTO。

## 5. 并发与可靠性

- 异步结果的异常分支必须处理，不留无人观测的 `CompletableFuture`。
- 不吞 `InterruptedException`；恢复中断状态或继续传播。
- 外部 I/O 设置连接与读超时；支持时响应中断或传入取消信号。
- 重试仅用于瞬态错误和幂等操作，使用最大次数、指数退避和抖动。
- 批量处理采用有界并发；线程池与连接池显式配置上限和队列策略，不用无界队列。
- 消息、Webhook 和重放请求按业务要求使用幂等键或唯一约束。
- 共享可变状态使用正确的可见性或同步；虚拟线程下不依赖未清理的 `ThreadLocal`。
- 进程关闭时停止接收新任务，有界等待在途任务并关闭依赖连接。

## 6. 数据库

- SQL/JPQL 值必须参数化；动态标识符来自 allowlist。
- 唯一性、外键、非空和范围等关键不变量尽量由数据库约束保证。
- 事务边界只覆盖必须原子化的写入，事务内避免慢网络调用。
- schema 变更使用迁移工具，考虑新旧应用并存时的向前/向后兼容；生产不使用运行时自动改表。
- 大表变更、回填和删除字段使用分阶段策略，并记录恢复方法。
- 关注 N+1、懒加载越界和连接池耗尽等持久化层常见问题。

## 7. 认证与安全

- 密码使用成熟密码哈希组件和项目认可参数，敏感比较使用定时安全比较。
- JWT 明确允许算法，验证签名、过期时间及所需 issuer/audience；禁止代码内默认密钥。
- Session 使用安全 cookie 属性并防止固定攻击；登出和密码变更按契约撤销会话。
- CORS 只允许明确来源；反向代理环境明确转发头策略。
- 敏感接口使用限流；上传限制大小、类型、数量和路径。
- 授权检查基于服务端事实，不能信任客户端传入的 userId、role 或 tenantId。
- 生产环境关闭或限制调试端点、详细错误堆栈和敏感的运维端点。

## 8. 日志与可观测性

- 使用 SLF4J 参数化日志，包含 request id/correlation id 和必要业务上下文。
- 同一错误只在有完整上下文的一层记录一次，避免重复日志。
- 对 Authorization、cookie、token、密码、连接串和个人数据脱敏。
- 健康检查区分 liveness 与 readiness；指标避免高基数标签。
- 不在循环或高频路径打印调试日志；日志级别应可运行时调整。

## 9. 测试

- 单元测试覆盖纯业务规则；集成测试覆盖 HTTP、持久化和中间件契约。
- 使用临时数据库、隔离 schema 或事务策略，禁止连接生产环境。
- 覆盖成功、边界、非法输入、依赖失败、超时、权限和并发路径。
- 避免固定 `Thread.sleep`；使用可控时钟、可注入随机源或确定性同步工具。
- 分层与依赖方向可用 ArchUnit 之类的静态架构测试固化。

## 10. 依赖和发布

- 新依赖前检查现有依赖和 JDK 标准库能否满足，说明维护与安全成本。
- 不手工篡改版本解析结果；依赖变更后运行项目认可的审计和测试。
- 数据库迁移、应用发布和任务消费者的顺序必须明确。
- 发布、部署、推送和生产操作必须由用户明确授权。

## 11. 改动记录格式

时间精确到秒——同一天多次改动很常见，只到分钟不足以区分先后。

```md
## YYYY-MM-DD HH:mm:ss

- 目标：
- 改动：
- 验证：
- 未验证/风险：
```
