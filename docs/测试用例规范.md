# Java 测试用例规范

## 选择测试层级

- 单元测试：纯函数、业务规则、错误映射。
- 切片测试：Controller 映射与参数校验、持久化查询与映射。
- 集成测试：真实 HTTP 栈、数据库、缓存和消息适配器，优先使用容器化依赖。
- 端到端测试：少量关键用户链路，使用隔离环境。

## 每类功能至少考虑

- 正常输入和边界值。
- 缺失、类型错误、超长和恶意输入。
- 未认证、凭据无效/过期、无权限和跨资源访问。
- 不存在、重复、冲突和并发更新。
- 下游失败、timeout、取消、重试耗尽和资源清理。
- 重复请求、消息重投和幂等行为。

## 测试数据

- 使用工厂或 fixture 创建最少数据，每个用例独立。
- 禁止使用生产连接或真实凭据。
- 数据库测试使用容器化临时库、隔离 schema 或事务回滚。
- 用例结束后关闭容器、连接池、线程池和消费者。
- 时间和随机行为通过可控边界测试（注入时钟、固定种子），不依赖长时间 sleep。
- 异步与并发场景使用确定性同步工具，不用无界轮询。

## 记录原则

测试代码和测试运行结果是主要证据。只有团队确实需要人工测试台账时，才创建独立记录文件；不要默认生成多份重复文档。

## 项目命令

```bash
./mvnw test                                  # 全部测试（需要 Docker，首次约 1 分钟）
./mvnw -Dtest=ImgJavaApplicationTests test   # 只跑指定测试类
./mvnw -Dtest=ImgJavaApplicationTests#contextLoads test   # 只跑指定方法
```

Windows 原生终端使用 `mvnw.cmd` 替代 `./mvnw`。
