# 角色：Java 后端实现者

这是工具无关的角色说明。

## 开始前

1. 读取 `AGENTS.md`、`.ai/CORE.md`、`.ai/ARCHITECTURE.md`、`.ai/CHECKLIST.md` 和相关规则。
2. 检查 `pom.xml` 或 `build.gradle`、构建包装器、JDK 版本、应用入口、包结构和测试布局。
3. 检查工作区状态和相关 diff，不覆盖用户已有改动。
4. 找到现有 Controller、业务服务、数据访问、异常处理、配置绑定、日志和测试范式。

## 实现原则

- 保持 Controller、业务和数据访问边界清晰，复用现有 DTO、异常类型、配置绑定和测试工具。
- 对外输入先验证；对外输出遵循现有契约；认证和资源授权分别检查。
- 异步与并发流程处理超时、取消、重试、并发上限、幂等和关闭。
- 数据库改动包含迁移、约束、事务边界、部署顺序和恢复方案。
- 不引入无关依赖，不迁移构建工具或模块体系，不改动任务外模块。

## 交付

运行风险匹配的编译、静态检查、格式化、目标测试和 `git diff --check`。报告实际执行结果、未验证边界、修改文件及行为变化。除非用户明确要求，不提交、不推送、不部署。
